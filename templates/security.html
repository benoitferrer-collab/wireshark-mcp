02 / IDENTITÉS & AUTORISATIONS

Deux accès. Deux décisions.

Se connecter ne suffit pas : chaque canal applique ses propres règles d’autorisation.

CANAL 01APPLICATION WEB

Votre espace d’analyse,
derrière Microsoft.

  1. Connexion au tenant configuréLe serveur vérifie la signature, l’émetteur, l’audience, les dates, le tenant et le nonce du jeton d’identité.
  2. Propriétaire ou groupe autoriséLe propriétaire conserve l’administration. Les autres utilisateurs sont vérifiés contre le groupe configuré ; contrôle renouvelé au plus tard après cinq minutes ou un changement de politique.
  3. Session serveur protégéeCookie Secure, HttpOnly, SameSite=Lax ; données de session chiffrées en base et identifiant haché. Vérification d’origine et jeton CSRF pour les opérations de session qui modifient l’état.
Navigateur → session Web autorisée → API d’analyse
CANAL 02SERVEUR MCP

Un outil ne s’exécute
qu’avec le bon jeton.

  1. Jeton OAuth Microsoft déléguéVérification RS256, expiration, émetteur, audience, tenant et version du jeton. Aucun accès MCP anonyme.
  2. Identité explicitement autoriséeL’identifiant utilisateur doit appartenir à la liste MCP autorisée. Cette liste est distincte du groupe d’accès Web.
  3. Permission pcap:read obligatoireLa connexion OAuth doit porter la permission déléguée attendue. Un compte Microsoft quelconque ou une clé API de modèle ne suffit pas.
Client IA → jeton OAuth → identité + scope → outil PCAP

Les exigences MFA et d’accès conditionnel relèvent des stratégies de votre tenant Microsoft. Le périmètre actuel est un espace partagé entre les identités autorisées. Il n’est pas présenté comme une isolation des captures par utilisateur ou une plateforme multitenant.

03 / MOINDRE PRIVILÈGE

Le PCAP est le périmètre.
Le catalogue est la frontière.

Le MCP expose un ensemble explicite d’outils d’investigation. Un appel à un outil inconnu ne devient pas une commande système : il est refusé.

DANS LE PÉRIMÈTRE
  • Rechercher et corréler des preuves
  • Inspecter paquets et conversations
  • Calculer statistiques et diagnostics
  • Lire les métadonnées TLS disponibles
HORS CATALOGUE
  • Exécuter un terminal arbitraire
  • Envoyer un e-mail ou un message
  • Modifier une configuration réseau
  • Soumettre une clé TLS via le MCP

Outils dédiés ≠ conversation filtrée. Une question générale posée à Claude peut recevoir une réponse sans aucun appel MCP. Le produit ne prétend pas bloquer cette conversation.

    05 / PROTECTION DES PREUVES

    Partager ce qui aide.
    Limiter ce qui expose.

    La minimisation s’applique dans les projections MCP. Les captures et leurs secrets n’ont pas le même circuit.

    ⌁

    Des métadonnées sélectionnées

    Les nouveaux outils TShark retournent des champs protocolaires autorisés : adresses, ports, horaires et références. Ils ne retournent pas les payloads bruts, cookies, en-têtes Authorization, corps HTTP ou paramètres d’URL HTTP.

    Les vues historiques appliquent un filtrage par noms de champs. Cela ne constitue pas une anonymisation universelle de toutes les données capturées.
    ◇

    Des secrets TLS à part

    L’ajout de clé RSA ou de SSLKEYLOGFILE passe par le Web autorisé. L’outil MCP TLS lit uniquement un rapport déjà produit ; il ne prend pas de clé privée et ne lance pas le déchiffrement.

    La disponibilité d’un rapport dépend du traitement effectif par le worker TLS, pas de cette page.
    ≋

    Une exécution bornée

    TShark lit un fichier résolu par le stockage, avec des arguments fixes et sans shell. La résolution de noms est désactivée ; la configuration utilisateur du moteur est isolée.

    Une lecture PCAP hors ligne ; aucune capture réseau active exposée par le catalogue MCP.

    LIMITE À CONNAÎTRE

    Connecté ne signifie pas
    contrôlé de bout en bout.

    Le bon fonctionnement de LiteLLM a été déclaré par l’administrateur. Cette page ne sonde pas ses politiques et ne certifie pas leur activation.

    Une connexion directe au MCP conserve ses contrôles Azure AD, mais ne traverse pas les garde-fous du proxy. Leur caractère obligatoire nécessite un contrôle supplémentaire d’accès à l’amont.

    Le proxy MCP ne voit pas automatiquement toute la conversation ni la réponse finale du modèle. Une détection d’injection n’est jamais une garantie absolue.
